# Chaincheck

Собственный инструмент проверки EVM-платежей без своей ноды. Ethereum, BNB Smart Chain, Polygon, Arbitrum One, Base, X Layer.

## Использование

Выберите сеть, вставьте хеш. Для валидации укажите ожидаемые получателя, точную сумму и контракт ERC-20. Для нативной монеты выберите соответствующий актив. Можно дополнительно указать отправителя. Порог подтверждений задаёт оператор; значение 12 является настройкой интерфейса, а не рекомендацией по финальности.

Статус «Соответствует всем условиям» появляется только при успешном receipt, совпадении данных двух RPC, включении в текущий канонический блок, достаточной глубине и точном совпадении одного перевода со всеми реквизитами. Совпадение только названия токена не используется. Суммы обрабатываются целочисленно через BigInt. События ERC-721/1155 и внутренние native-переводы не поддерживаются. Fee включает gasUsed × effectiveGasPrice и l1Fee, если поле присутствует; дополнительные специфические комиссии сети могут не входить.

Сверка с ожидаемым контрактом не доказывает добросовестность эмитента или стандартность контракта. Только USDT0 в X Layer включён в справочник по официальным данным: https://docs.usdt0.to/technical-documentation/deployments. Для остальных токенов оператор должен брать адрес из проверенного справочника компании/эмитента.

JSON-отчёт содержит исходные transaction/receipt и блоковые данные от обоих RPC, ожидаемые реквизиты, время и результат проверки. Это снимок ответов, а не подписанное доказательство. История последних 20 пар сеть/хеш хранится только в localStorage браузера. Серверная БД не используется. Хеши и адреса передаются поставщикам RPC; инфраструктура хостинга и RPC может вести технические логи.

## Запуск и проверка

Node.js 22+; внешние зависимости не нужны.

```powershell
node scripts/preview.mjs
node scripts/test.mjs --live
node scripts/build.mjs
node scripts/validate-artifact.mjs
```

Открыть http://127.0.0.1:8787. Тесты используют сохранённый публичный sample-report.json как fixture и изолированные имитации отказов. --live дополнительно проверяет chain ID всех RPC.

POST /api/check принимает JSON с network, hash, recipient, sender, contract, amount, asset (erc20/native), minConfirmations. Эндпоинт выполняет только ограниченный набор RPC для шести фиксированных сетей. Произвольные RPC URL и методы не принимаются. Не передавайте сюда приватные ключи.

## Эксплуатация в компании

Текущий Site закрыт владельцу; общего доступа сотрудникам и серверного журнала действий пока нет. Для постоянной нагрузки нужны управляемые RPC двух разных операторов с API-ключами на сервере и лимитами запросов; публичные RPC могут ограничивать частоту и архивные eth_call. Своя нода не требуется. Два официальных RPC X Layer принадлежат одной экосистеме и не считаются независимыми операторами. Настройки RPC находятся в NETWORKS в worker/index.js.

Повторное использование одного хеша для двух заявок не отслеживается. Для автоматического зачисления необходим отдельный реестр использованных сеть+txHash+logIndex и правила финальности по каждой сети. Этот интерфейс предназначен для ручной проверки, не выполняет зачисления, AML и проверку владельца адреса. L2-подтверждения не заменяют L1-финальность.

Источники JSON-RPC: https://ethereum.org/developers/docs/apis/json-rpc/ ; X Layer: https://web3.okx.com/onchainos/dev-docs/xlayer/developer/build-on-xlayer/network-information ; Base: https://docs.base.org/get-started/connect-to-base ; Arbitrum: https://docs.arbitrum.io/chain-info .
