# GitHub Pages

Публичный сайт: https://jimbokl.github.io/chaincheck/

Сборка без зависимостей: `node scripts/build-pages.mjs`. В репозитории Pages публикует каталог `/docs` ветки `main`. Пересоберите `docs` и отправьте изменения для обновления.

Браузер импортирует те же проверяющие функции, что и Worker-версия. Запросы `/api/check` и `/api/wallets` обрабатываются локально в браузере, после чего обращения идут напрямую к публичным RPC и индексаторам. Сервер, своя нода, API-ключи и кошелёк не требуются. Не добавляйте секреты в исходники Pages: они публичны.

## Покрытие

| Сеть | Транзакция | Балансы адресов | История |
| --- | --- | --- | --- |
| Ethereum, BSC, Polygon, Arbitrum, Base, X Layer | Receipt, блок, ERC-20 события, сверка двух RPC, точная валидация реквизитов | Нативная монета + выбранный ERC-20 на одном блоке | Выбранный ERC-20 по диапазону: X Layer 100 блоков, остальные 1000; переход назад |
| TON | Сверка TON и Jetton по финализированному действию и успешной транзакции получателя. Для Jetton используется адрес master | TON, выбранный Jetton master | Страницы сообщений TON |
| TRON | Сверка TRX и TRC-20 по solidified-транзакции и квитанции. Для TRC-20 используется адрес контракта | TRX, выбранный TRC-20 | Страницы TransferContract TRX либо выбранного TRC-20 из TronGrid |
| Solana | Сверка SOL и SPL по финализированной транзакции. В отчёте указан один или два ответивших RPC. Для SPL используется mint и адрес владельца или token account | SOL, сумма выбранного SPL mint | Страницы подписей со ссылкой на аккаунт |
| Bitcoin | Сверка одного выхода BTC по двум индексаторам с настраиваемым порогом подтверждений | Подтверждённый баланс и изменение mempool | Страницы по 25 подтверждённых транзакций |

Для сверки раскройте «Сверить с ожидаемым платежом» и укажите актив, получателя и точную сумму. Если одинаковая сумма пришла несколькими отдельными переводами или выходами, отчёт передаёт платёж на ручную сверку. В Bitcoin выход может быть сдачей. Выбирайте порог подтверждений по правилам вашей компании. Для произвольных TRC-20 точность читается из текущего solidified состояния контракта. Для Token-2022 требуется подтверждение зачисленной суммы изменением баланса token account.

В режиме «Определить по хешу» сайт ищет транзакцию в поддерживаемых сетях с подходящим форматом идентификатора. При одном совпадении открывает транзакцию, при нескольких предлагает выбрать сеть. Частичный ответ или недоступность источников отображаются в результатах поиска. Проверка адресов выполняется в выбранной сети.

Состояние адреса сверяется с двумя источниками там, где это возможно, и только при совпадении привязки к блоку/слоту/LT. Для транзакций TRON используется TronGrid, для доставки TON и Jetton — TON Center. Источник истории указан в отчёте. Названия токенов от индексаторов не подтверждают эмитента.

Публичные сервисы имеют ограничения частоты, CORS и архивной глубины. Отказ отображается как ошибка/неполная проверка, а не нулевой баланс или отсутствие истории. История адресов не сохраняется на сервере. Недавние EVM-хеши хранятся в localStorage. Не передавайте приватные ключи.

Тесты: `node scripts/test.mjs`; `node scripts/test-wallets.mjs`. Дополнительный `--live` проверяет доступность источников. `sample-report.json` содержит публичные данные исходной X Layer транзакции для регрессионных проверок.

Источники API: https://ethereum.org/developers/docs/apis/json-rpc/ ; https://docs.tonconsole.com/tonapi/rest-api/accounts/ ; https://docs.ton.org/ecosystem/api/toncenter/v3/overview ; https://developers.tron.network/docs/get-trc20-transaction-history ; https://solana.com/docs/rpc/http ; https://github.com/Blockstream/esplora/blob/master/API.md .
